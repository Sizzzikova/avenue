# Бот автопостинга акций «Авеню»

Раз в сутки в 10:00 по Москве скачивает страницы `/aktcii/` трёх городов и
сравнивает их с тем, что было вчера.

* Появились новые авто со скидкой или что-то подешевело → в канал уходит
  **один пост** со всеми изменениями сразу.
* Ничего не изменилось → **пост не выходит вообще**, прогон завершается молча.

Работает с Telegram и с MAX (второй включается, когда будет токен).

## Что на самом деле лежит на странице акций

Это важно понимать до правки кода. Раздел «Акции» на сайте «Авеню» — **не список
текстовых анонсов**, а блок «Автомобили со скидкой»: карточки конкретных машин
с ценой, характеристиками и, иногда, сроком действия скидки. Поэтому пост
строится вокруг автомобиля, а не вокруг заголовка акции.

Два следствия:

* **Цены в HTML нет.** В разметке стоит заглушка `#N/A`, реальную цену страница
  подставляет джаваскриптом. Бот повторяет тот же запрос: `POST /ajax/calc_catalog.php`
  с полем `id=<id авто>` возвращает JSON с `dayPrice` и `originalPrice`, из них
  считается процент скидки. Если эндпоинт не ответил, в пост уходит базовая цена
  из атрибута `static-price`, без старой цены и процента.
* **Микроразметки с офферами на странице нет** — только `Organization`/`WebSite`/`Store`,
  одинаковые для всех трёх городов. Стратегии «сначала JSON-LD, потом RSS» не
  получилось: остались CSS-селекторы, зато все они вынесены в `config.yml`.

## Быстрый старт

```bash
cd avenue-promo-bot
pip install -r requirements.txt

# посмотреть, что бот собирается опубликовать, ничего не отправляя
PYTHONPATH=src python -m avenue_bot.main --mode dry-run

# тесты парсера и шаблона поста
python -m pytest -q
```

## Режимы запуска

| Режим | Что делает |
|---|---|
| `dry-run` | Скачивает, разбирает и печатает в консоль пост, который вышел бы прямо сейчас. Ничего не шлёт, состояние не трогает. Значение по умолчанию. |
| `seed` | Записывает все текущие акции как «уже виденные», не публикуя ничего. |
| `run` | Боевой режим: публикует изменения, если они есть. |

Дополнительно: `--city nsk` ограничивает прогон одним городом (ключ из `config.yml`),
`--verbose` включает подробный лог.

### Первый запуск — обязательно `seed`

Без него первый же боевой прогон вывалит в канал сразу все действующие акции
(сейчас их семь на три города) — бот ведь не знает, что они не новые. Порядок такой:

1. Actions → «Акции Авеню» → Run workflow → режим `dry-run`. Убедиться, что сайт
   доступен и акции распознаны.
2. Тот же workflow в режиме `seed`. В репозиторий закоммитится `state/seen.json`.
3. Дальше расписание работает само: в канал попадут только акции, появившиеся
   после сида.

## Секреты

Задаются в Settings → Secrets and variables → Actions. В коде и конфиге токенов нет.

| Секрет | Зачем |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_CHAT_ID` | Канал для постов: `@имя_канала` или числовой `-100...` |
| `TELEGRAM_ADMIN_CHAT_ID` | Служебный чат для алертов о поломках |
| `MAX_BOT_TOKEN` | Токен бота MAX (нужен только при `messengers.max.enabled: true`) |
| `MAX_CHAT_ID` | Канал в MAX |

Если секретов Telegram нет, отправитель просто пропускается с предупреждением
в логе — прогон не падает.

## Как всё устроено

```
src/avenue_bot/
  models.py     Promo: город, авто, цена, скидка, сроки, отпечаток
  config.py     чтение config.yml + секретов из окружения
  fetch.py      HTTP с таймаутами и ретраями, браузерный User-Agent
  parse.py      разбор карточек по CSS-селекторам из конфига
  prices.py     дозагрузка цен через /ajax/calc_catalog.php
  state.py      state/seen.json: что уже публиковали
  render.py     сборка текста поста, лимиты и экранирование
  senders/      telegram.py, max_messenger.py — независимые отправители
  alerts.py     сообщения о поломках в служебный чат
  main.py       CLI и сценарий прогона
```

### Что считается изменением

`state/seen.json` хранит записи вида `"<город>:<ссылка на авто>"` → отпечаток
(sha256 от названия, цены, скидки, сроков и плашек), последняя цена, даты первого
показа и публикации. На каждом прогоне бот сравнивает страницу с этой записью:

| Что на сайте | Что делает бот |
|---|---|
| Авто, которого раньше не было | В пост, раздел новинок |
| Цена упала больше чем на `price_drop_percent` и держится два прогона | В пост, раздел «обновились цены», со строкой «было … стало» |
| Цена упала меньше порога | Молчит, точку отсчёта не двигает — накопившееся снижение заметит позже |
| Цена упала, а назавтра вернулась | Молчит: разовый провал не подтвердился |
| Цена выросла | Молчит и точку отсчёта не двигает |
| Поправили описание или плашку | Молча обновляет отпечаток |
| Авто пропало со страницы | Убирает из состояния, в канал не пишет |
| Ничего не поменялось | Ничего не отправляет |

Подорожание и косметические правки не идут в канал специально: хвастаться там
нечем, а каждая мелкая правка на сайте иначе превращалась бы в пост. Если хочется
получать только новинки и вообще не реагировать на снижение цен — поставьте
`post.include_changes: false` в `config.yml`.

### Почему со снижением цен столько предосторожностей

Цену бот берёт не из вёрстки, а из живого калькулятора сайта
(`/ajax/calc_catalog.php`) — в HTML её просто нет. Калькулятор считает цену
каждый раз заново, и одно и то же предложение день ото дня может отдавать чуть
разные числа. Ещё он иногда не отвечает, и тогда подставляется базовая цена из
вёрстки — другое число по другой методике.

Поэтому «цена снизилась» объявляется только при совпадении трёх условий:

1. **Обе цены из одного источника.** Цену из калькулятора с ценой из вёрстки бот
   не сравнивает никогда: их разница означает «сайт полежал», а не «подешевело».
2. **Снижение больше порога** `post.price_drop_percent` (по умолчанию 5%).
3. **Снижение держится два прогона подряд.** Разовый провал не подтверждается
   на следующие сутки и в канал не попадает. Настоящее снижение цены выйдет
   постом на день позже — для суточного бота это нормальная плата.

Точка отсчёта — это цена, которую в канале назвали в последний раз. Вверх она не
двигается: иначе после подорожания возврат к прежней цене бот объявил бы скидкой,
хотя про подорожание подписчикам никто не говорил.

Если постов про снижение всё равно многовато, поднимите `price_drop_percent`
до 10–15. На прогонах с искусственным дрожанием цен ±3% порог 5% даёт ноль ложных
постов за 60 суток, и при этом настоящее снижение на 20% замечается за один день.

Города, которые в этом прогоне не скачались, при чистке не трогаются — иначе одна
сетевая ошибка стёрла бы историю и следующий прогон опубликовал бы всё заново.

### Как выглядит пост

Когда изменение одно, выходит обычный пост с фотографией автомобиля. Когда их
несколько — дайджест, сгруппированный по городам:

```
🔥 Что нового в акциях «Авеню»

📍 Новосибирск
• Exeed TXL 4WD — кроссовер, 2022
  8 400 ₽/сут вместо 11 000 ₽ (−24%)
  https://avenuerent.ru/autopark/cars/Exeed-TXL-car713/
• Toyota Camry 70 — седан, 2019
  7 000 ₽/сут
  https://avenuerent.ru/autopark/cars/car162/

📍 Иркутск
• Nissan Roox — хэтчбэк, 2021
  3 000 ₽/сут
  https://irkutsk.avenuerent.ru/autopark/cars/nissan-roox-car575/

💰 Обновились цены

📍 Горно-Алтайск
• Exeed TXL 4WD — кроссовер, 2023
  8 900 ₽/сут — было 9 500 ₽
  https://gorno-altaysk.avenuerent.ru/autopark/cars/exeed-txl-0001/

✅ Без залога, КАСКО в цене, доставим по адресу
```

У дайджеста фотографии нет: несколько машин в одном посте одной картинкой не
покажешь. Если для канала важнее картинки, чем компактность, поставьте
`post.mode: separate` — тогда на каждый автомобиль выйдет отдельный пост с фото.

### Расписание

Задаётся в `.github/workflows/avenue-promos.yml`, строка `cron`. Сейчас
`'0 7 * * *'` — 10:00 по Москве (в cron время в UTC, Москва круглый год UTC+3).

| Когда постить | cron |
|---|---|
| Ежедневно в 10:00 МСК | `0 7 * * *` |
| Ежедневно в 19:00 МСК | `0 16 * * *` |
| Дважды в сутки, 10:00 и 19:00 МСК | `0 7,16 * * *` |
| Каждый час | `0 * * * *` |

GitHub ставит запуски по расписанию в очередь, поэтому фактическое время может
съехать на 10–30 минут вперёд. Повлиять на это нельзя; если пост обязан выходить
минута в минуту, нужен свой сервер с обычным cron.

Файл состояния коммитится обратно в репозиторий от имени `github-actions[bot]`
с пометкой `[skip ci]`. Побочный плюс: регулярные коммиты не дают GitHub отключить
расписание после 60 дней тишины в репозитории.

### Защита от тихой поломки

Если страница отдала HTTP 200 и непустое тело, но карточек найдено ноль — это
почти наверняка изменившаяся вёрстка, а не «акций нет». В этом случае бот:

* **не трогает** состояние по этому городу;
* пишет в служебный чат, что сломались селекторы;
* завершается с ненулевым кодом, и прогон в Actions виден красным.

Без этой проверки поломка была бы незаметной: посты просто перестали бы приходить.

## Пост вышел, хотя на сайте ничего не менялось

Разбирать в таком порядке — по тексту вышедшего поста сразу понятно, куда смотреть.

**Пост вида «🔥 Новые авто со скидкой — 7 автомобилей», то есть разом весь список.**
Значит, бот не увидел сохранённого состояния. Откройте последний прогон в Actions
и посмотрите шаг **«Сохранить состояние»**: если он красный или писал «Push не
удался», `state/seen.json` не доехал до репозитория, и на следующие сутки бот
посчитал новыми все акции. Проверьте, что у workflow есть `permissions: contents: write`
и что ветка не защищена правилом, запрещающим пуш от `github-actions[bot]`.
Сейчас на этот случай стоят две страховки: при пустом состоянии и при «новыми
оказались вообще все акции» бот отказывается публиковать, пишет в служебный чат
и падает красным.

**Пост вида «💰 Цены снизились».** Сработал калькулятор сайта — см. раздел выше.
Поднимите `post.price_drop_percent` до 10–15 или выключите реакцию на цены
совсем: `post.include_changes: false`.

**Пост про одну-две машины, которые на сайте давно.** Скорее всего, у них
поменялись адреса страниц или внутренние id. Состояние привязано к id
автомобиля (`data-car` в вёрстке), но если поменялся и он — узнать акцию не по чему.
Проверьте в `state/seen.json`, под какими ключами лежат записи.

Посмотреть, что бот думает прямо сейчас, не отправляя ничего:

```bash
cd avenue-promo-bot
PYTHONPATH=src python -m avenue_bot.main --mode dry-run
```

Он напечатает либо готовый пост, либо «Изменений нет — пост не вышел бы».

## Что делать, если сайт переверстали

Симптом: в служебный чат пришло «не найдено ни одной карточки», прогон красный.

1. Сохранить свежую страницу: `curl -sS https://avenuerent.ru/aktcii/ > tests/fixtures/nsk.html`
   (и так же для `irkutsk`, `gorno-altaysk` с их поддоменов).
2. Открыть её и найти новый селектор карточки автомобиля. Сейчас это
   `div.cars__item.js-car-data`.
3. Поправить нужные строки в разделе `selectors` файла `config.yml` — код менять
   не требуется.
4. Обновить ожидаемое число акций в `EXPECTED_COUNTS` в `tests/test_parse.py`
   и прогнать `python -m pytest -q`.

Селекторы и их назначение:

| Ключ | Что ищет |
|---|---|
| `card` | Корень карточки автомобиля. Каждое совпадение = одна акция. |
| `title_link` | Ссылка с названием модели. |
| `data_anchor` | Служебная ссылка с `data-car`, `data-link`, датами скидки. |
| `image` | Фотографии авто, берётся первая. |
| `labels` | Плашки «Новинка», «Правый руль». |
| `body_type` | Тип кузова. |
| `properties` | Привод, коробка, мощность, объём — распознаются по содержимому, а не по порядку. |
| `year` | Год выпуска. |

## Как временно выключить бота

Любой из способов:

* Actions → «Акции Авеню» → «⋯» → Disable workflow. Расписание перестаёт срабатывать.
* Или в `config.yml` выставить `messengers.telegram.enabled: false` — прогоны
  продолжатся вхолостую, состояние будет обновляться, но посты не уйдут.
  Осторожно: после включения обратно пропущенные акции уже помечены виденными
  и опубликованы не будут.

Отключить только MAX (например, пока не готов токен): `messengers.max.enabled: false`.

## Ограничения, о которых стоит помнить

* **Раннеры GitHub Actions стоят в США.** Российские сайты нередко закрыты для
  зарубежных IP. Проверяется отдельным workflow «Проба сети» (`.github/workflows/probe.yml`),
  запуск вручную. Если сайт оттуда не открывается — переносим запуск на российский
  хостинг (Yandex Cloud Functions с таймером и состоянием в Object Storage, VPS в РФ
  с обычным cron, либо self-hosted runner). Код при этом не меняется.
* **API мессенджера MAX ещё меняется**: домен `botapi.max.ru` объявлен устаревшим
  в пользу `platform-api.max.ru`, способ передачи токена в разных версиях
  документации отличается. Отправитель шлёт токен и заголовком, и параметром;
  адрес API задаётся в `config.yml`. Перед боевым запуском стоит сверить формат
  запроса с dev.max.ru и при расхождении поправить `_build_payload`
  в `senders/max_messenger.py`.
* **Расписание в GitHub Actions работает только с ветки по умолчанию.** Пока код
  в рабочей ветке, доступен лишь ручной запуск.
